# 基于Lakehouse架构的游戏市场热度感知平台

## 项目简介

本项目基于 **Lakehouse** 架构，构建一个完整的游戏数据分析平台。通过调用 Steam 平台公开 API，采集热门top10游戏的历天销量、评论、评分等数据，经过 ODS → DWD → DWS → ADS 四层 ETL 加工，最终同步至 MySQL ，为下游 BI 看板提供数据支撑。

> 🎯 从数据采集到数据服务的全链路数据工程项目

### 项目依赖
- Java 8 or 11
- Hadoop 3.3.6
- PySpark 3.5.3 + Iceberg 1.7.0
- Python 3.12.3
- MySQL + PowerBI

## 技术栈选型

| 组件 | 技术选型                | 说明                            |
|------|---------------------|-------------------------------|
| **表格式** | Apache Iceberg      | 支持 ACID、快照隔离、时间旅行、Schema 演化   |
| **存储层** | HDFS                | 分布式文件系统，存算分离架构的基础             |
| **计算引擎** | PySpark + Spark SQL | 采集用 Python（灵活），ETL 用 SQL（易维护） |
| **调度平台** | DolphinScheduler    | 可视化工作流编排，支持依赖检查、补数、告警         |
| **数据看板** | MySQL+PowerBI       | PowerBI 连接 MySQL 可视化核心指标      |


## 数据分层模型

| 分层 | 命名规范 | 说明 |
|------|----------|------|
| **ODS 层** | `ods_steam_{实体名}` | 保留 API 原始 JSON 快照，按 `dt` 日期分区，禁止修改 |
| **DWD 层** | `dwd_steam_{事实/维度名}` | 清洗非法数据、解析 JSON 嵌套结构、处理缺失值，数据打宽 |
| **DWS 层** | `dws_steam_{主题}_1d` | 按天聚合计算游戏热度、评分趋势、销量排行等宽表 |
| **ADS 层** | `ads_steam_{指标名}` | 生成最终看板指标表，字段即报表展示字段 |

## 核心功能模块

### 1. 数据采集（ODS 写入）
- **输入**：Steam API 返回的游戏售价、评论、评分、销量（基于appid+steamid销量唯一性、该维度评论数量即反映销量） JSON 数据。
- **输出**：写入 HDFS Iceberg 表 `ods_steam_game` 和 `ods_steam_review`
- **容错机制**：支持指数退避重试（API 限流）、Schema 动态容错（缺失字段填空）。

### 2. 数据清洗与建模（DWD 层）
- **清洗规则**：过滤空值、去重（基于游戏 ID + 时间戳）、JSON 打宽（嵌套结构展开）。
- **输出**：生成事实表（`dwd_steam_review`）和维度表（`dwd_steam_game`），数据质量通过 `CHECK` 约束验证。

### 3. 汇总聚合（DWS 层）
- **计算逻辑**：按 `dt` 分组，统计每个游戏每日销量、评论数、好评率。
- **输出**：`dws_steam_trend_1d` 宽表，作为 ADS 层的唯一数据来源。

### 4. 看板指标（ADS 层）\export层
- **核心指标**：近 7 天销量 & 销售额排行、游戏好评率排行榜、日度GMV增长趋势。
- **输出**：`ads_steam_dashboard` 表，结构优化，直接对接 Superset。

### 5. 数据导出（ MySQL 同步）
- **同步方式**：Spark JDBC 批量写入（Batch Insert）
- **同步频率**：每日 ADS 层产出后触发一次，保证看板数据 T+1 更新。

### 6. 全链路调度（DolphinScheduler）
- **DAG 定义**：ODS 完成 → DWD 启动 → DWS 启动 → ADS 启动 → Hologres 导出。
- **异常处理**：任务失败自动重试 3 次，超过后发送告警（邮件/钉钉）。
- **补数功能**：支持指定日期区间补跑历史数据。
